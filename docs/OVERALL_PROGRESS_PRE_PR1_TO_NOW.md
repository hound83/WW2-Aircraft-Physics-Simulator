The P47 starting climb comparison uses the stronger configuration-conditioned fit already present before PR1 (44.83 ft/min), rather than advertising the raw 546.39 ft/min baseline as wholly new progress. P47 speed improved substantially, but its overall climb gain against that prior fit is modest. The 41-5931 climb observations and 41-5902 speed/power reference are different specimens; these are engineering transfer benchmarks.

Mustang speed error increased by about 1.23 mph while climb agreement improved sharply. That is a real tradeoff. Mustang climb uses the same assumed 9335-lb, 2200-ft, ram-critical scenario at 67/75 inHg; one point participated in fitting. Spitfire climb retains source weight/configuration and qualified boost inputs. Bf109 has no supported climb score. No averaged headline percentage combines these different metrics.

## What the releases changed

- Added a shared propeller/drag engineering fit and explicit source-climb power/configuration treatment. Clean and source-climb scenarios remain separate in the same core solver.
- Added source specimen/configuration and airspeed-convention guards, calculation-domain limits, visible missing inputs, and fixed source-state browser comparisons.
- Preserved the legacy C numerical baseline separately from working-model performance. Regression and browser checks improve software reliability; they do not prove historical accuracy.
- v3.2 adds original-scan provenance correction and fixed-model high-altitude checks. It makes zero coefficient changes, so the above numerical gains were achieved by v3.1.

Historical turn/stall accuracy and a 5:1 comparative-accuracy target remain unproved. CLmax assumptions have not gained a demonstrated historical accuracy improvement.

## Next useful iteration

Resolve the Spitfire 32000-ft transcription against original pixels, obtain same-specimen engine/propeller conditions for P47, then evaluate a physically bounded high-altitude power model against reserved observations. Accept new coefficients only if they improve those checks while preserving clean-speed performance. More unrelated observations would not resolve these specific missing inputs.

See [v3.2 evidence and new checks](V32_HIGH_ALTITUDE_VALIDATION.md) and [v3.1 reserved-point comparisons](V31_CLIMB_IMPROVEMENT.md). Run node validation/diagnostics/overall_progress.cjs or npm run check to regenerate the current comparison.
